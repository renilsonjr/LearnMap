# Comments — Code Exercises

Write real, runnable Python for each item below. Put your solutions in your own subfolder inside this topic folder (e.g. `Frodo/`, `Maverick/`), one script per exercise, then open a PR per [../../instrucoes.MD](../../instrucoes.MD).

## Easy
1. Write a script with a single-line comment above a function explaining its purpose, then call the function.
2. Write a function with a one-line docstring, then print `function.__doc__` to show it's accessible at runtime.
3. Rewrite a function that has a comment on every line (over-commented) into a cleaner version with just one useful comment.

## Medium
4. Write a function with a docstring and also a `# comment` on the same line as some code, printing `__doc__` to show the difference between the two.
5. Take a confusing one-line piece of code and add both a "bad" comment (restates the code) and a "good" comment (explains why) as two separate versions.
6. Write a script with a `# TODO:` and a `# FIXME:` comment marking incomplete work and a known bug, respectively.
7. Write a module with a module-level docstring at the top and a function with its own docstring below; print both `__doc__` values.

## Hard
8. Write a function with a Google-style or NumPy-style docstring (Args/Returns/Raises sections) and print it.
9. Write two versions of the same function: one with a comment that's now inconsistent with the code below it (a stale comment causing confusion), and the corrected version.
10. Refactor a function full of explanatory comments into self-documenting code (better names, extracted helper functions) that needs little to no comments; keep both versions to compare.

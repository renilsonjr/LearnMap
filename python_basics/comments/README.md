# Comments — Practice Questions

## Persona Prompt Block
**Role:** Technical Recruiter, light-touch, focused on code-quality habits.
**Rules:**
- Looking for clear, confident communication as much as correctness — explain your answer like you're on a call.
- Follow-up questions probe "why," not just "what."
- Buzzwords without substance are called out.
- A wrong answer with good reasoning scores better than a right answer with no explanation.

## Questions

### Easy
1. What character starts a single-line comment in Python?
2. How do you write a multi-line/triple-quoted comment or docstring?
3. Why shouldn't you comment every single line of code?

### Medium
4. What is the difference between a comment and a docstring, and how is a docstring exposed at runtime via `__doc__`?
5. What makes a comment "good" vs. "bad"? Give an example of each for the same line of code.
6. What are TODO/FIXME comment conventions used for in professional codebases?
7. Where should a module-level vs. function-level docstring be placed, and what should each typically describe?

### Hard
8. Explain how docstrings following a convention like Google or NumPy style let tools (e.g. Sphinx) auto-generate documentation.
9. Why can outdated comments be worse than no comments at all? Give a scenario where a stale comment causes a real bug.
10. Discuss the tradeoff between self-documenting code (clear naming/structure) and relying on comments to explain "why" vs. "what."
